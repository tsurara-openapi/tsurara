# tsurara-client (Rust)

The runtime library for Rust code generated by tsurara (`language: rust`). Generated functions pass an OperationDef to `Client::request`, which builds the request, sends it through a `Transport` (reqwest with rustls by default), and returns `Result<Success<S>, Failure<E>>`. It implements the runtime contract in `spec/` and passes its conformance vectors. It re-exports `serde` and `serde_json`, so generated code needs no other dependency.

Install it with `cargo add tsurara-client`, at the version of the generator's release.

Features: `client` (the client, Results, retries and sequences; tokio), `reqwest` (the default transport; enables `client`), and `testing` (the mock transport). The default is `client` and `reqwest`. Types generated with `operations: false` need neither: `default-features = false` keeps `Nullable`, `File` and `tagged_union!` only.

```rust
use tsurara_client::{Client, ErrorBody, Failure, Retry};
use std::time::Duration;

let client = Client::builder("https://api.example.com")
    .header("user-agent", "my-app")
    .timeout(Duration::from_secs(10))
    .retry(Retry::default())
    .auth(|scheme, _op| (scheme.scheme == "api_key").then(|| std::env::var("API_KEY").ok()).flatten())
    .build();

// Generated: get_pet(client, pet_id, GetPetOptions) -> ApiResult<Pet, Problem>
match get_pet(&client, 1, Default::default()).await {
    Ok(pet) => println!("{}", pet.data.name),
    Err(Failure::Http { status: 404, body: ErrorBody::Documented(problem), .. }) => println!("{problem:?}"),
    Err(other) => return Err(other.into()), // Failure implements std::error::Error
}
```

## Results

`Ok(Success { status, data, headers, operation })` for a success status of the definition. `Err(Failure)` otherwise:

| Variant | `kind()` | When |
|---|---|---|
| `Http { status, body, .. }` | `http` | An error status; `body` is `ErrorBody::Documented(E)` for a documented status, `ErrorBody::Undocumented(Payload)` otherwise (also a 2xx when other successes are documented) |
| `Network { cause, .. }` | `network` | The transport failed |
| `Timeout { .. }` | `timeout` | The timeout passed (over all attempts) |
| `Parse { .. }` | `parse` | The body does not match the definition (Content-Type, JSON, the type) |
| `Unexpected { cause, .. }` | `unexpected` | The input cannot be sent (for example a path parameter that would change the path) |

Dropping the future cancels the call; there is no `aborted` result.

### Streams

`Client::request_items::<T, E>` reads a success item by item (`parseAs` `events`, `jsonLines` or `jsonSeq`): it returns once the headers have arrived, with `Items<T>` as `data`.

```rust
let mut events = stream(&client, Default::default()).await?.data;
while let Some(event) = events.next().await {
    match event? {
        StreamEvent::StreamNoteEvent(n) => println!("{}", n.data.id),
        _ => {}
    }
}
```

Reading stops at the first `ItemError` (a broken connection, or an item that is not valid JSON or does not match `T`). Dropping `Items` closes the response; the timeout covers sending and the headers, not the wait for items. The client reads every response through `Transport::send_streaming`: `ReqwestTransport` reads the body as it arrives, and a transport that only implements `send` hands over the whole body at once.

## Options

| Builder method | |
|---|---|
| `transport` | Another `Transport`: a configured `ReqwestTransport(reqwest::Client)`, or your own (tests, WASM). The default follows redirects within the origin of the request only (a redirect to another origin is the result, spec/README.md); a `reqwest::Client` you pass follows its own redirect policy |
| `header` | A header for every request |
| `timeout` | Over all attempts of a call; the `timeout` field of a generated function's options per call |
| `retry` | `Retry::default()`: idempotent methods, network failures and 408, 429, 500, 502, 503, 504, up to 2 retries, `Retry-After` honored, otherwise backoff with jitter |
| `auth` | The credential for a security scheme of the operation; placed by the scheme (API key header, query or cookie, `Authorization: Bearer`, `Basic` for `user:password`) |
| `on_undocumented_status`, `on_result` | Observation hooks |

Without the default `reqwest` feature the crate has no HTTP client; give it a `Transport`.

## Testing without a server

The `testing` feature has `tsurara_client::testing::MockTransport`, a `Transport` that answers from handlers routed by operation (spec/README.md, Mock transports). Clones share the recorded calls:

```rust
use tsurara_client::testing::{MockResponse, MockTransport};

let mock = MockTransport::new()
    .base_path("/v1")
    .route("GET", "/pets/{petId}", |req| {
        Ok(MockResponse::json(200, &serde_json::json!({ "id": req.params["petId"], "name": "Pochi" })))
    });
let client = tsurara_client::Client::builder("https://api.test/v1").transport(mock.clone()).build();
// ... call generated functions, then inspect mock.calls()
```

`.operation(&def, handler)` routes by an OperationDef. A handler error, and a request no route matches, are `Failure::Network`; with `.record_unmatched()`, unmatched requests are answered with 501 and kept in `mock.unmatched()`.
