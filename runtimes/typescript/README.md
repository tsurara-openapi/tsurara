# @tsurara/client

The runtime library for TypeScript code generated by tsurara. Generated call functions pass an `OperationDef` to `client.request`, which serializes the request, calls `fetch`, and returns a `Result` that never rejects. See `docs/design.md` chapter 8 for the API.

```ts
import { createClient, unwrap } from '@tsurara/client';
import { getPet } from './generated/index.ts';

const api = createClient({ baseUrl: 'https://api.example.com' });
const result = await getPet(api, { path: { petId: 1 } });
if (result.ok) console.log(result.data);
const pet = unwrap(await getPet(api, { path: { petId: 1 } })); // throws ApiError on failure
```

## Authentication

Operations carry their security requirements from the definition. Give the client an `auth` function that returns the credential for a scheme, and it places it where the scheme says (header, query or cookie for API keys, `Authorization: Bearer` for bearer and OAuth tokens, `Authorization: Basic` for `user:password`):

```ts
import type { SecuritySchemeName } from './generated/index.ts';

const api = createClient({
  baseUrl: 'https://api.example.com',
  auth: (scheme) => {
    const name = scheme.scheme as SecuritySchemeName;
    if (name === 'api_key') return process.env.API_KEY;
    if (name === 'petstore_auth') return getAccessToken();
    return undefined;
  },
});
```

The first alternative for which every scheme gets a credential is used; operations with `security: []` send nothing.

## Typed errors

`ApiError` takes the operation's Result type (the generated `{Operation}Result`), which narrows `error.result` to that operation's failures: after `result.kind === 'http' && result.documented`, `result.error` has the documented error schema type. A thrown value has no static type, so give the type where the operation is known. With TanStack Query, that is the `TError` type argument:

```ts
import { type ApiError, unwrap } from '@tsurara/client';
import { type TodosListResult, todosList } from './generated/index.ts';

const todos = useQuery<Todo[], ApiError<TodosListResult>>({
  queryKey: ['todos'],
  queryFn: async () => unwrap(await todosList(api)),
});
if (todos.error?.result.kind === 'http' && todos.error.result.documented) {
  showProblem(todos.error.result.error); // the documented error type, such as Problem
}
```

Checking only `result.status === 422` does not narrow `error`: the member for undocumented statuses has `status: number`, so it stays. Check `documented` too, or use `isHttpError`, which does both:

```ts
import { isHttpError } from '@tsurara/client';

const result = await todosUpdate(api, { path: { id }, body });
if (isHttpError(result, 422)) {
  showProblem(result.error); // the documented 422 body
}
```

`isHttpError` accepts the documented error statuses of the operation. A status documented on its own narrows to its member; when the operation has a `default` (or a range such as `4XX`), any other status is accepted and narrows to that member with `status` set to the value. Without `default`, a status the operation does not document is a type error.

A shared handler that narrows with `error instanceof ApiError` gets `ApiError<AnyResult>`, because `instanceof` cannot know the operation. Cast once there, to the union of the Result types it handles (`error as ApiError<TodosListResult | TodosUpdateResult>`), or register a default error type for every query (`declare module '@tanstack/react-query' { interface Register { defaultError: ApiError<TodosListResult | TodosUpdateResult> } }`).

## Validation

`validate: validateResponses(responseSchemas)` validates JSON response bodies with [Standard Schema](https://standardschema.dev) schemas (the Zod schemas tsurara generates with `typescript.validators: zod`, or Valibot, ArkType, your own). A body with issues returns `{ ok: false, kind: 'validation', status, value, issues, response }`. The client depends on no validation library.

## Server-Sent Events

A `text/event-stream` response whose events the definition describes (`itemSchema`, or `x-itemSchema` before OpenAPI 3.2) is an async iterable of typed events, with JSON data already parsed:

```ts
const result = await stream(api, { signal });
if (result.ok) {
  for await (const e of result.data) {
    if (e.event === 'note') show(e.data);
  }
}
```

JSON Lines and JSON text sequences with an item schema are read the same way, one parsed item per iteration. Leaving the loop closes the connection. For an event stream without a schema, `parseEventStream(result.data)` reads the same events with `data` as a string.

## Testing without a server

`@tsurara/client/testing` has a `fetch` that answers from handlers routed by operation (spec/README.md, Mock transports). It is a separate entry point, so production bundles do not include it.

```ts
import { createClient } from '@tsurara/client';
import { mockFetch } from '@tsurara/client/testing';
import { getPetByIdDef } from './generated/operations/getPetById.ts';

const mock = mockFetch(
  [{ operation: getPetByIdDef, handler: ({ params }) => ({ status: 200, json: { id: Number(params.petId), name: 'Pochi' } }) }],
  { basePath: '/v1' },
);
const api = createClient({ baseUrl: 'https://api.test/v1', fetch: mock.fetch });
// ... call generated functions, then inspect mock.calls
```

Routes are `{ operation, handler }` or `{ method, path, handler }`; handlers return `{ status, json }`, `{ status, text, contentType }` or `{ status, bytes }`, and a handler that throws is a `network` failure. A request no route matches is a `network` failure naming it, or, with `unmatched: 'record'`, a 501 recorded in `mock.unmatched`.

## React Native and Expo

The client uses web globals only where they exist, so it runs without `ReadableStream`, `AbortSignal.any` or `DOMException`.

- Metro does not resolve `./foo.js` to `foo.ts`: generate with `typescript.importExtension: none`.
- Files are uploaded as React Native file objects: `reactNativeFile({ uri, name, type })` passes one where a generated multipart part expects `Blob | File`.
- Streaming responses (`parseAs: 'stream'`, `'events'`, `'jsonLines'` and `'jsonSeq'`) need a `fetch` with streaming bodies, such as `expo/fetch`: `createClient({ fetch })`. Without one they return `kind: 'parse'`.

Not yet checked on a device.

## Installing

```sh
npm install @tsurara/client
```

Use the version of the generator's release: `tsurara` and `@tsurara/client` are released together.

## Version check

Generated code records the compatible `@tsurara/client` range, and `tsurara check` compares it with `node_modules/@tsurara/client/package.json`: run it in CI to notice when the generator and the runtime drift apart.
